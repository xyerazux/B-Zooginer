## Architecture Rules (Never Violate)

### 1. No Supabase calls in components
All Supabase interactions must go through `src/services/*.service.ts`. Components call hooks in `src/hooks/`; hooks call service functions; service functions call Supabase.

```
Component → Hook (TanStack Query) → Service Function → Supabase Client
```

**Wrong:**
```tsx
// ❌ Never do this in a component
const { data } = await supabase.from('orders').select('*');
```

**Right:**
```tsx
// ✅ Use a hook
const { data: orders } = useGroupOrders(groupId);
```

### 2. No service role key in frontend
`SUPABASE_SERVICE_ROLE_KEY` is used **only** in Edge Functions (`supabase/functions/`). It must never appear in `src/`, `.env.local` for the frontend, or be committed to Git.

Frontend environment variables must only be:
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

### 3. TypeScript types come from the database
All database-related types must derive from `src/types/database.types.ts`, which is generated by:
```bash
supabase gen types typescript --linked > src/types/database.types.ts
```
Do not hand-write duplicate type definitions for database tables.

### 4. RLS is the security layer
Never trust the client-side role check alone. All access restrictions are enforced by Supabase RLS policies. When adding a new table or operation:
- Write the RLS policy first
- Document it in `docs/SECURITY.md`
- Test it with the anon key AND the appropriate JWT

### 5. No direct orders table INSERT by anon key
Public order submission goes **only** through the `submit-order` Edge Function. The `orders` table must not have an anon-INSERT RLS policy.

### 6. Entire UI must use Bahasa Indonesia
All user-facing text, button labels, badge texts, forms, validation messages, toasts, dialogs, empty states, and dashboard navigation must be in proper Bahasa Indonesia (e.g. "Pesanan Baru", "Belum Bayar", "Lunas", "Kirim Pesanan", "Input Pesanan Manual").

### 7. Multi-dimensional product variants
Products support multiple variant dimensions (e.g., Size AND Flavor). Dimension configurations are stored in `products.variant_dimensions` (JSONB array), and purchasable combinations in `product_variants` with `title` and `attributes` (JSONB object). Never hardcode a single dimension.

### 8. Anonymous public access with secure high-entropy access token
Public visitors access the storefront anonymously. Order confirmation lookup strictly requires both `order_code` and `access_token` via the `get_order_confirmation` RPC to prevent order enumeration and protect student PII.

## Coding Conventions

### TypeScript
- Strict mode is enabled — no `any` types
- Prefer `type` over `interface` for plain data shapes; use `interface` for extendable component props
- Use `Database['public']['Tables']['orders']['Row']` pattern or derived aliases

### React
- Functional components only; no class components
- Extract logic into custom hooks — keep components lean (< 150 lines preferred)
- Use `React.lazy` + `Suspense` for all admin page routes (code splitting)
- Error boundaries wrap admin route trees

### Naming
| Thing | Convention | Example |
|-------|-----------|---------|
| Components | PascalCase | `OrderStatusBadge.tsx` |
| Hooks | camelCase with `use` prefix | `useGroupOrders.ts` |
| Services | camelCase with `.service` suffix | `orders.service.ts` |
| Pages | PascalCase with `Page` suffix | `OrderDetailPage.tsx` |
| Types | PascalCase | `Order`, `OrderItem`, `GroupWithProducts` |
| Enums | UPPER_SNAKE_CASE values | `order_status: 'new' | 'confirmed' | ...` |

### Tailwind
- Use semantic class groupings, not raw utility strings scattered inline
- Extract repeated patterns into shared components — do not duplicate `className` strings
- Never use arbitrary values (`w-[237px]`) unless absolutely necessary
- Use the design system tokens defined in `tailwind.config.ts`

### Forms
- All forms use React Hook Form + Zod resolver
- Zod schemas are defined in the same file as the form component or in `src/lib/schemas/`
- Never use uncontrolled inputs without React Hook Form

## Database Conventions

- All tables use `uuid` primary keys with `gen_random_uuid()` default
- All tables have `created_at timestamptz default now()` and `updated_at timestamptz default now()` with an update trigger
- Soft-delete only: use `is_active = false` for products, `is_published = false` for groups
- Enums are defined as PostgreSQL custom types, not CHECK constraints
- Never DELETE from `orders` or `activity_logs`

### Migration Files
- Named: `YYYYMMDDHHMMSS_description.sql`
- One logical change per file
- Never edit a migration that has been applied to production — write a new one

## Order Code Format

```
BZG-YYYYMMDD-XXXX
```
- `BZG` — platform prefix (fixed)
- `YYYYMMDD` — UTC date of order
- `XXXX` — 4-character alphanumeric random suffix (uppercase, no ambiguous chars: no 0/O, 1/I/L)

Generated server-side only, in the `submit-order` Edge Function or via `generate_order_code()` PostgreSQL function.

## Common Gotchas

> [!WARNING]
> **Do not use `supabase.auth.admin.*` from the frontend.** These Admin API methods require the service role key. Create an Edge Function if admin user management is needed.

> [!WARNING]
> **Do not add an anon INSERT policy to the `orders` table.** Public ordering is intentionally routed through the Edge Function for server-side validation and order code generation.

> [!CAUTION]
> **Never call `supabase.from('orders').delete()`** anywhere in the codebase. Orders are never deleted — set `order_status = 'cancelled'` instead.

> [!NOTE]
> When adding a new Supabase table, regenerate `database.types.ts` immediately with `supabase gen types typescript --linked > src/types/database.types.ts`.

> [!NOTE]
> TanStack Query mutation invalidation: after any mutation that changes `orders`, invalidate `['orders']` and `['reports']` query keys.

## Quick Commands

```bash
# Local dev
npm run dev                        # Start Vite dev server
supabase start                     # Start local Supabase
supabase db reset                  # Reset local DB + apply migrations + seed

# Type generation
supabase gen types typescript --linked > src/types/database.types.ts

# Tests
npm run test                       # Vitest
npm run test:ui                    # Vitest UI

# Build
npm run build                      # Production build
npm run preview                    # Preview production build locally

# Deploy
supabase db push                   # Apply migrations to linked Supabase project
supabase functions deploy submit-order
# (Vercel deploy is triggered by git push to main)
```
